3Description

ARK-3 is a complete, reproducible ad-ranking stack built on a -impression sample of the Criteo click logs. A DeepFM ranker models second-order and deep feature interactions over 39 embedded fields. A two-tower model, trained to imitate that ranker, maps contexts and ads into one vector space so FAISS can shortlist candidates; DeepFM then re-scores only the shortlist.

The ranker is exported to ONNX and served from a C++ harness built on ONNX Runtime, where thread placement and buffer reuse are tuned against a fixed request shape: one context × candidates.

7Detailed Description

7.1Overview

A request arrives with a context (the 34 context pins). Stage one encodes it with the query tower; stage two asks a FAISS IVF index for the catalog items with the highest tower score; stage three runs DeepFM on exactly those pairs and returns the top-10 by predicted click probability. The offline benchmark compares that output against an oracle that runs DeepFM on every one of the catalog items.

7.3Feature Description

7.3.1 Field Encoding

Count features (I1–I13) are discretised: values ≤ 2 keep their own bucket, larger values map to ⌊ln²(x)⌋, the transform used by the winning Kaggle Criteo solutions. Categorical features (C1–C26) get a train-only vocabulary with a frequency floor of . Every field then indexes one shared embedding table ( rows); per-field offsets live inside the model so the exported graph consumes the raw int64[B, 39] tensor.

7.3.2 DeepFM Ranker

DeepFM (Guo et al., 2017) sums three terms that read the same 16-d embeddings: a first-order linear term, the factorisation-machine pairwise term ½[(Σv)² − Σv²], and a 400-400-400 MLP with batch norm and dropout. Training uses Adam, evaluates on validation four times per epoch, decays the learning rate on every non-improving evaluation, and stops after two. Embedding L2 is chosen per configuration on validation log loss — DeepFM overfits within its second epoch without it.

7.3.3 Ad / Context Split

Retrieval needs an item side, but Criteo's fields are anonymous. Attributes of one entity are functionally dependent, so for every pair of categorical fields the sheet computes the normalised conditional entropy U(J|K) = H(J|K)/H(J) (Figure 6-6). High-cardinality fields that pin down several others (U < ) are candidate ad keys. Several qualify, so each candidate catalog is scored by the trained DeepFM and the entity whose ranking depends most on the query is kept (Table 7-1): , carrying . The catalog is the most frequent keys, each with its modal attributes.

7.3.4 Two-Tower Retrieval, Distilled from the Ranker

Both towers embed their fields and pass them through a 256-128-64 MLP to unit-norm vectors. A click-trained tower (in-batch sampled softmax with logQ correction) learns what gets clicked, but the funnel must find what DeepFM will rank highest. The distilled tower therefore minimises KL(teacher ‖ student) between the softmax of DeepFM logits and of tower scores over slates of 128 uniformly sampled items plus the student's own current top-64 (hard negatives). Each item also learns a scalar bias stored as an extra vector coordinate (the query appends a constant 1), so inner-product search in FAISS reproduces the tower score exactly.

7.3.6 ONNX Export and C++ Harness

The ranker is exported (opset 18, dynamic batch, sigmoid in-graph) and verified against PyTorch on 20,000 held-out rows (max |Δp| = ). cpp/bench.cpp replays real fine-ranking requests through ONNX Runtime and reports latency percentiles.

      8.2Layout Guidelines

      • Size the shortlist from Figure 6-3, not from habit: the distilled tower's retention curve flattens well before the click-trained tower's does.
      • Retrieval quality is bounded by agreement with the ranker, not by click AUC — distil the ranker into the retriever.
      • On CPU, pin intra-op threads to the knee of Figure 6-4 instead of the core count, and keep request buffers alive across calls.
